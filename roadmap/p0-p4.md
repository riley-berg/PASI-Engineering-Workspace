# PASI Unified Agent Kernel Roadmap

This is the checked-in architecture spine for the Better Hermes transformation. Existing Orchestrator, Planner, Runner, Provider, Recovery, Evidence, and Computer-Use features are being consolidated into a single Agent Kernel and a typed Capability System.

## Target architecture

`Autonomous Supervisor → Agent Kernel → Capability System → external integrations`

AI workers are ephemeral and replaceable. The Kernel owns durable state, scheduling, evidence, recovery, runtime revision, and authorization.

### Agent Kernel

- **Virtual Scheduler** — merges Orchestrator + Planner into one dependency-aware execution scheduler.
- **State & Evidence Matrix** — canonical identity, lifecycle, desired/actual state, evidence predicates, provenance, and operation ledger.
- **Runtime Revision Engine** — candidate / stable / previous-stable runtime identity and promotion/rollback.
- **Routing Core** — model/provider selection, local-first execution, escalation, and budget policy.
- **Worker Contract** — stateless workers receive bounded context and return structured action requests/results.

### Capability System

- **Workspace OS** — terminal, filesystem, Git, GitHub, process/resource observation.
- **Browser Engine** — browser lifecycle, CDP, extension, tab/session identity, browser proof, and acceptance workloads.
- **Integration Platform** — PASI MCP, Runtime API, dashboard projections, and external adapters.

### Autonomous Supervisor

- deterministic failure classification;
- bounded recovery and retry;
- loop detection and escalation;
- candidate verification and quarantine;
- blue/green promotion and runtime rollback;
- evidence-driven continuous self-healing.

## Phase spine

### P0 — Runtime proof & kernel readiness
Finish current-CDP M2 recovery, 168-hour endurance, delivery gates, and the migration audit that maps every active subsystem into the Kernel/Capability/Supervisor boundaries.

**Gate:** live runtime behavior is proven with authoritative evidence.

### P1 — Unified Agent Kernel & State Matrix
Create the exclusive Kernel boundary and make the Evidence/State Matrix authoritative for task, operation, runner, recovery, verification, and runtime-revision state.

**Gate:** a live operation can be interrupted, reconstructed, resumed, verified, and stopped from durable Kernel state without worker-local truth.

### P2 — Capability System & Integration Platform
Turn terminal, filesystem, Git/GitHub, browser/CDP/extension, PASI MCP, Runtime API, and host interactions into typed capabilities with explicit bounds and evidence contracts.

**Gate:** agents perform real work only through Kernel-granted capabilities.

### P3 — Autonomous Supervisor & Evidence-Driven Recovery
Move recovery, loop detection, candidate quarantine, promotion/rollback, and escalation outside the model loop.

**Gate:** the Supervisor can recover bounded failures, stop non-progressing loops, and roll a failed candidate back without corrupting source.

### P4 — Agent Workers, Model Routing & Engineering Memory
Make model workers replaceable. Route routine work to local models, escalate difficult work under policy, and compile bounded task context from durable memory and evidence.

**Gate:** a task can switch workers/models mid-operation without losing identity, state, or evidence.

### P5 — Trust, Security & Autonomous-Action Policy
Apply Observe → Edit → Apply → Promote → Push trust levels across all capabilities and protect the Kernel/Supervisor/promotion path from model-authored mutation.

**Gate:** every privileged action is policy-authorized, bounded, auditable, and reversible.

## Engineering continuation

P6+ builds engineering-domain capabilities on top of the Kernel. These phases must not introduce competing orchestration, planning, recovery, model-routing, or authorization systems.

P13 becomes the specialist-agent layer that consumes the shared worker/capability contracts.

P20 becomes measured engineering self-optimization using the already-existing Supervisor, candidate, evidence, verification, and rollback machinery. It is not the point where autonomous control is first invented.

## Non-negotiable architectural rules

1. **One control plane.** Orchestrator, Planner, Runner Registry, Recovery, Evidence, and blue/green lifecycle are Kernel concerns.
2. **One capability boundary.** Workers do not receive unrestricted shell, filesystem, browser, Git, or API access.
3. **Evidence beats assertions.** Readiness, completion, recovery, promotion, and rollback require authoritative evidence predicates.
4. **Source ≠ runtime.** Git pull/fetch never implies runtime deployment.
5. **Candidate promotion is transactional.** Candidate → apply → verify → promote; failure → preserve evidence → rollback runtime.
6. **Workers are disposable.** Any compatible model can continue from Kernel state.
7. **Self-healing is deterministic first.** Model diagnosis is an escalation mechanism, not the source of truth.
8. **No parallel legacy architecture.** Once a replacement is authoritative, obsolete APIs, duplicate state machines, compatibility shims, and superseded runner/control paths are removed.
9. **Acceptance workloads are not control planes.** M1 and 168-hour runs validate the Kernel; they do not become permanent top-level architectures.

## Definition of done

Every major capability requires a typed contract, policy bounds, authoritative evidence, provenance, failure handling, resource limits, observability, reproducible acceptance where practical, and an explicit deprecation/removal path.

The model cannot declare a state transition, readiness result, recovery success, promotion, or rollback success without the corresponding evidence.
