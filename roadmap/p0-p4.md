# PASI Engineering Workspace Roadmap

This is the executable engineering spine for the automation program.

## P0 — Runtime proof

Establish deterministic validation, local provider execution, operation evidence, and bounded end-to-end task execution.

- M0: one real task through authenticated ChatGPT response handoff, contract parsing, patch application, canonical validation, committed evidence, and a clean worktree; M0 must reuse the durable automation chat and may create a fresh chat only after an explicit ChatGPT usage/context limit, with Thinking enabled and bounded connection-loss stop/resume from a durable checkpoint using the same operation identity.
- M0 prompt progression: the current task prompt is immutable while the task is incomplete; exactly one new prompt is generated after verified completion, derived by the harness from the next task plus the verified prior-task evidence/state, and never precomputed inside the current task prompt.
- M1: 20 consecutive operations with exact operation identity and no duplicates; task-to-task prompt progression must be durable and task-specific.
- M2: interruption followed by exact-operation recovery with no duplicate execution.
- Long-run: bounded unattended operation after M0–M2.

## P1 — Control-plane consolidation

Unify operation state, durable events, recovery classification, failure signatures, and bounded repair loops.

## P2 — Planner, scheduler, and engineering memory

Version the roadmap, select eligible work, generate bounded tasks, preserve evidence/provenance, and maintain durable project memory.

## P3 — Provider-neutral model infrastructure

Add capability metadata, deterministic provider selection, health monitoring, fallback, local model profiles, and PASI-specific benchmarks.

## P4 — Typed computer integration

Add explicit capabilities for terminal, IDE, browser, Git, and other applications. Computer control remains separate from model inference and never becomes a DOM model transport.
