# PASI Engineering Workspace Roadmap

This is the executable engineering spine for the automation program.

## P0 — Runtime proof — COMPLETE
Establish deterministic validation, local provider execution, operation evidence, and bounded end-to-end task execution.
- M0: completed runtime task proof.
- M1: completed 20-operation identity/duplicate proof.
- M2: completed interruption and same-operation recovery proof.
- Long-run: sustained unattended execution path implemented and exercised; the project explicitly waives the additional 168-hour human soak requirement.

P0 completion does not mean future tasks may close on test-green alone. All subsequent work uses `docs/engineering-completion-standard.md`.

## P1 — Control-plane consolidation — IN PROGRESS
1. **Unified versioned operation state** — canonical schema, lifecycle transitions, revision/CAS semantics, durable state store, and restart persistence.
2. **Durable event model** — ordered events with correlation, timestamps, source, and immutable evidence references.
3. **Operation ledger and lineage** — task/operation/run relationships and durable lineage queries.
4. **Deterministic recovery classification** — typed recovery causes, bounded actions, and decision evidence.
5. **Failure-signature registry** — normalized failure fingerprints with provenance and lifecycle.
6. **Bounded repair-loop controller** — finite retries, explicit stop conditions, and preserved failure evidence.
7. **Safe runtime-state migration** — version-aware migrations with validation and rollback protection.

## P2 — Planner, scheduler, and engineering memory
Version the roadmap, select eligible work, generate bounded tasks, preserve evidence/provenance, and maintain durable project memory.

## P3 — Provider-neutral model infrastructure
Add capability metadata, deterministic provider selection, health monitoring, fallback, local model profiles, and PASI-specific benchmarks.

## P4 — Typed computer integration
Add explicit capabilities for terminal, IDE, browser, Git, and other applications. Computer control remains separate from model inference and never becomes a DOM model transport.
